# v0.4 PS2 retail cheat-system trace — SLUS_209.04 — 2026-10-22

Target: *The SpongeBob SquarePants Movie* (USA), PS2 executable `SLUS_209.04`,
SHA-256 `2ff117f45e80be5e2d73b6c952f4b5adfb8d359c8cc6c14eb5906197994ce956`.
Method: static disassembly of the retail ELF plus a whole-codebase cross-reference
census (address formation, `$gp`-relative accesses, `jal` targets). Function
**names** are taken from the bfbbdecomp/tssm references (`zGameExtras.h`,
`zGameExtras.cpp`, DWARF line maps) as labels only — **no GameCube address was
transplanted**; every address, byte pattern, and caller below was verified in
the PS2 binary itself. ELF facts: VA = file offset + 0xFFF80; `$gp = 0x0063DBF0`.

Confidence key: **confirmed** = instruction-level evidence in the retail binary;
**inferred** = behavioral match with alternatives considered.

| `g_gameExtraFlags` | `0x00636FA0` | written by the calendar check |

| `sCheatPressed[16]` | `0x0066A820` | input window; newest press at `[15]` = `0x0066A85C` |
| `cheatList[10]` | `0x005FBCB0` | 9 active `GECheat` records + null terminator; record = `{key_code*, fun_cheat, flg_keep, flg_mode}` |
| key-code arrays | `0x005FBA70`–`0x005FBCB0` | 9 × 16 words; words 0–7 are zero, words 8–15 are the 8 presses |

Only two button codes appear in any sequence: **Circle `0x20000`** and
**Square `0x80000`** — the handler masks new presses with `0xA0000`, so no
other button can ever enter the window (confirmed at `0x002D283C`).

Complete write census for `g_flg_chEnabled` (every `sw` to `0x00636FA4` in the
binary): update loop `0x002D2950` (toggle) and `0x002D2964` (add);
`zGameExtras_Load` `0x002D2AA0` (OR-in saved bits); Extras reset zero-stores at
`0x002C4AD8` and `0x002C4F08`; Extras manager AND-clear at `0x002C3894`. There
are no other writers — this bounds where flag manipulation can live.

## The five requested functions

### 1. `zGameCheatsUpdate` → retail `0x002D2740`–`0x002D2A7C` — CONFIRMED

First words: `27bdffd0 24030007 ffbf0020 7fb10010`. Single caller: `jal` at
`0x002D2D20`, inside the zGameExtras scene-update function.

Behavior, all read from the retail code:

- Returns immediately unless `*(0x00636FB0) == 7` (the cheat-entry game state).
- Reads pad `on` (+0x2C) and `pressed` (+0x30); start-over conditions mirror the
  reference locals (unmasked bits present, `0x3300` combo, `0xA0000` held).
- While `sCheatInputCount > 0`, `sCheatTimer` decays by `dt`; on expiry the
  sequence is abandoned (failure handling below).
- On a new tracked press: appends it (see `AddToCheatPressed`), plays the
  `CHEAT_STEP_GRP` step sound (string `0x0061FF7B`, hash lookup `0x0044DEA0`,
  play `0x00455880`), then scans `cheatList` until a record with
  `key_code == 0`.
- On a match: updates the flag word (see `GEC_CheatFlagToggle`/`Add`), then
  calls the record's callback with `jalr` through record+4 at `0x002D2974`,
  then plays `CHEAT_SUCCESS` (string `0x0061FE77`).
- On no match with presses recorded: plays `CHEAT_FAILED_GRP` (string
  `0x0061FF8A`), resets the timer to 2.0, clears the window with a `memset`
  call (`0x001182E0`, 0x40 bytes at `0x0066A820`) and zeroes
  `sCheatInputCount`. With a partial match pending, the reset is quiet and the
  timer is set to -1.0 (`0x002D2A40` path).

### 2. `TestCheat` → INLINED in `zGameCheatsUpdate` at `0x002D28F0`–`0x002D2928` — CONFIRMED (inlined)

The retail binary has **no standalone `TestCheat`**. The test is an inlined
16-word backward compare of `key_code[15..0]` against `sCheatPressed[15..0]`
inside the record scan (compare base formed at `0x002D28F4`). Proof of "no
other copy": `sCheatPressed` is referenced from nowhere else in the binary.

### 3. `AddToCheatPressed` → INLINED in `zGameCheatsUpdate` at `0x002D2840`–`0x002D2888` — CONFIRMED (inlined)

No standalone function. The append is inlined at the head of the update: the
16-word window at `0x0066A820` is shifted down one slot (three unrolled
5-word chunks, `0x002D2840`–`0x002D2874`), then the masked new press
(`pressed & 0xA0000`, AND at `0x002D283C`) is stored at `sCheatPressed[15]`
(store at `0x002D2888`, in the delay slot of the step-sound lookup call).

### 4. `GEC_CheatFlagToggle` / `GEC_CheatFlagAdd` → INLINED in `zGameCheatsUpdate` — CONFIRMED (inlined)

No standalone functions exist in retail. On a match, at `0x002D2940`–`0x002D2964`:

- if `flg_mode & 1`: `g_flg_chEnabled ^= flg_keep` (`xor` at `0x002D2948`,
  store at `0x002D2950`) — the toggle;
- else: `g_flg_chEnabled |= flg_keep` (`or` at `0x002D2960`, store at
  `0x002D2964`) — the add.

The only other flag manipulator is the Extras manager's AND-clear loop at
`0x002C3850`–`0x002C38A8`, which clears other records' bits
(`g_flg_chEnabled &= ~entry_bit`) — a clear, not a toggle.

### 5. `zGameExtras_CheatFlags` → retail `0x002D2AC0` — CONFIRMED

The whole function is two words: `03e00008 8f8293b4` — `jr $ra` with the
delay-slot `lw $v0, -0x6C4C($gp)`, returning `g_flg_chEnabled` verbatim, exactly
matching the reconstructed reference body. Callers: `jal` at `0x0034BA78` and
`0x003591B0`.

### 6. `GEC_cb_RestoreHealth` → retail `0x002D2620`–`0x002D2730` — INFERRED (behavioral)

`cheatList[1]`: key array `0x005FBB70`, `flg_keep 0x00000100`, `flg_mode 0`
(add). It has **no direct `jal` callers** — it is reached only through the
record's function pointer, as expected for a table callback.

Retail behavior: stores `6` to `0x007AC084` and `6` to `0x007AC4F4` (the +0x14
word of the two player state structs, which sit 0x470 apart), stores byte `3`
to `0x007ABC01` and `0x007ABC02`, refreshes the shared ability table
(`0x005FC510`, count at `0x00636528`, match key 10), and triggers the HP UI
refresh flow (hash of `"PAUSESTATE MENU OR POWERUP COUNTER"` at `0x0061FEC4` →
object lookup `0x002EED90` → call `0x003EB940` with argument
`0x3C` only when the object exists and its +0x14 state equals 2). First words: `27bdfff0 24040006 ffbf0000 3c03007b`.

Naming note: the header generation calls this callback
`GEC_cb_RestoreHealth`; in the DWARF generation the same table slot is
`MaxHealthSlotsCB` (reference size 0x11C vs retail 0x110, the usual per-build
drift seen across this module). The retail behavior — writing the health-slot
words for both players plus the pause/powerup UI-refresh flow — is the health callback
under either name. No other callback writes health state.

## CORRECTION — 2026-10-22 (later the same day)

The first owner test of the cheat-seq ISO failed, and tracing the failure
found three errors in the original version of this document. The patch itself
and every code address, caller, and instruction in the trace above are
unaffected; the errors were labels and missing entry conditions.

1. **Button name.** The code `0x80000` is **Square** on the PS2 pad word, not
   Triangle (the decomp header comment that suggested Triangle does not match
   the retail PS2 layout). Decisive cross-check: with `0x20000` = Circle and
   `0x80000` = Square, all nine traced sequences match the nine published
   retail PS2 cheat codes exactly (GameFAQs listing: Double Manliness
   CCSSCSSC, health slots CCCCSCSC, all moves SSCSCCSS, Macho SSCSCCSC, all
   tasks CSCCSCSS, SpongeBob Caveman SSSSCSSS, Ripped Shorts SSSSCSSC,
   Goofy Goober Patrick SSSSCSCS, Patrick Caveman SSSSCSCC). Record
   identities in the table above follow from this match: record 0 = Double
   Manliness (its callback writes the ×2 multiplier), record 1 = all six
   health slots, records 5–8 = the four costume cheats.
2. **Globals addresses.** The `$gp`-relative cheat-module globals were
   mislabeled +0x600 too high. Correct values (`$gp = 0x0063DBF0` re-verified
   from `.reginfo`): flags `0x00636FA4`, timer `0x00636FA8`, input count
   `0x00636FAC`, extras flags `0x00636FA0`, day/month `0x00636F98`/`0x00636F9C`,
   game-state variable `0x00636FB0`. Every instruction address in the census
   was and remains correct.
3. **Entry method (was missing).** See the next section.

### What sets the game state to 7, and the verified entry method

The gate variable is `0x00636FB0` (`$gp-0x6C40`). It has exactly three writers
in the binary: the generic state setter at `0x002D1BC0` (stores its argument
at `0x002D1D24`; it special-cases transitions to/from 6 and 7), and the
front-end reset function at `0x002F7500` (stores 7 at `0x002F767C` on its
"_RETURN_FROM SAVE MGR" path). The setter is called with argument 7 from
three zGame pause-flow sites (`0x002D4008`, `0x002D45D4`, `0x002D4750`):
**state 7 is the paused state**. The cheat handler also enforces the entry
conditions itself (`0x002D2768`–`0x002D27BC`): it reads the player pad's `on`
(+0x2C) and `pressed` (+0x30) words, requires `(on & 0x3300) == 0x3300` —
**L1+L2+R1+R2 all held** — and accepts only Circle/Square presses (mask
`0xA3300` total); any other button, or releasing the shoulders, resets the
entry (the "startover" path). Published instructions for the retail game say
the same thing: press Start to pause, hold L1+L2+R1+R2, then enter the code.

Verified instructions for the original handler:
1. Start any level.
2. Press **Start** to pause.
3. **Hold L1+L2+R1+R2** and keep them held.
4. Press the 8-button Circle/Square sequence. Each accepted press plays the
   step jingle; a completed code plays CHEAT_SUCCESS; a failed entry plays
   CHEAT_FAILED_GRP after the entry timer expires.

Why the first test produced no sounds at all: the test ISO had never been
copied to the PS3 (an FTP listing of /dev_hdd0/PS2ISO taken during the
diagnosis still shows only the retail, DamageMenu and HealthMenu ISOs), the
instructions named Triangle instead of Square, and the pause-and-hold
conditions were missing. In gameplay, Triangle is the talk/interact button —
hence the characters talking. The patched ISO replaces the Patrick Caveman
code (□□□□ O □OO) with □□□□□□ OO; on the patched ISO the other eight codes
are unchanged.
