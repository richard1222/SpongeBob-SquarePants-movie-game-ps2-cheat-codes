# v0.4 Phase 3 — health-refill integration: design and Neptune validation — 2026-10-22

Target: *The SpongeBob SquarePants Movie* (USA), PS2 `SLUS_209.04`,
SHA-256 `2ff117f45e80be5e2d73b6c952f4b5adfb8d359c8cc6c14eb5906197994ce956`.
Brief: design and test the health-refill integration **on Neptune first**;
no console step in this phase. Phase 2 established that the retail health
cheat (cheatList[1], callback `0x002D2620`) grants six health slots but
never touches current HP. This phase integrates the missing half — restore
HP to max when the cheat fires — in the way the game itself does it.

**Status: built and validated on Neptune. NOT hardware-tested. The ISO has
not been copied to any console.**

## Design

### The heal operation (copied from the game's own code)

The retail full-heal sits at `0x00331504`–`0x0033150C` (a respawn/restore
flow): load the player pointer from `0x007ABC10`, copy the 32-bit field at
player+0x464 over the field at player+0x460. Field identities are proven
by the game's health-adjust routine at `0x0032262C`–`0x00322664`, which
adds a signed delta to player+0x460 (current HP) and then clamps it:
`if (player+0x464 < HP) HP = player+0x464` — so **+0x460 = current HP,
+0x464 = max HP, both 32-bit words** (every access via this pointer in the
binary is `lw`/`sw`; 165 load sites). Healing to the struct max can never
exceed any limit the game enforces.

### The detour (2 sites, 6 words)

1. **`0x002D26CC`: `nop` → `jal 0x0010F06C`** (word `0x0C043C1B`). This
   word is a compiler padding nop inside the retail callback, executed
   exactly once per invocation: the fall-through word after the
   unlockables-refresh loop, just before the HUD confirm tail. Register
   audit at that point: `$t0` (loop counter) is dead, `$t1` is unused in
   the whole callback, `$a0`–`$a3`/`$v0`/`$v1` are reloaded immediately
   after; the `jal`'s clobber of `$ra` is absorbed because the callback
   saved the handler's return address on its own stack at `0x002D2628`
   and restores it from there — the live `$ra` is not used after this
   point except by the leaf's return.
2. **Heal leaf at `0x0010F06C`** (five words replacing zero padding):
   ```
   lui  $t0, 0x7B
   lw   $t0, -0x43F0($t0)   ; $t0 = *(0x007ABC10)
   lw   $t1, 0x464($t0)     ; max HP
   jr   $ra
   sw   $t1, 0x460($t0)     ; delay slot: HP = max HP
   ```

Execution order on a successful cheat entry is now exactly retail, plus
one step: slots + bonus bytes → unlockables refresh → **heal** → HUD
confirm flow → return.

### Why that padding is safe to use (the cave hunt, with its dead ends)

This binary is densely referenced; several plausible spaces were checked
and **rejected on evidence** before the padding at `0x10F06C` was chosen:

- The large zero runs near `0x526A98`–`0x52A5A8` are the ELF's own dynamic
  metadata (the startup code at `0x1007FC`+ forms addresses into them).
- The 104-byte zero run at `0x4C5618` is a zero field inside a data table
  (dense nonzero entries follow it).
- Repeating 16-byte `jr $ra` stub units are everywhere, but almost all are
  reachable: as jump/branch targets, as raw pointer words, or — the subtle
  one — as **lui-pair computed addresses** (a four-unit field at
  `0x3C3C80` looked clean until a dispatcher at `0x3C4C94` was found
  computing all four entries). Branch targets matter too: the stub at
  `0x403B70` is the landing pad of a branch at `0x403B48`.
- Of all stub units, only four survive the full four-way check (control
  flow targets incl. relative branches, raw-word occurrences, computed
  addresses, interior targets), and three of those four still fail the
  fall-through test (a live loop or MMI block runs into them).

The chosen site passes everything: five zero words at `0x10F06C`–`0x10F07F`
sandwiched between a complete function epilogue (`jr $ra` at `0x10F064`,
stack restore in its delay slot — so nothing can fall through into them)
and the next function's first instruction at `0x10F080`; no instruction,
branch target, pointer word, or computed address anywhere in the 5.4 MB
executable references any of the five words (full-binary scans).

### Known boundaries

- If the unlockables table count (`*(0x00636528)`) were 0, the callback
  branches straight to its tail (`0x2D2658`) and the heal is skipped —
  slots still apply. The table is populated in retail; stated for
  completeness.
- The leaf dereferences the player pointer without a null check, exactly
  like the retail full-heal and the 165 other sites using this pointer.
  The cheat handler only runs while paused in a level, where the pointer
  is the active player.
- Open question the hardware test answers: whether the struct max
  (+0x464) already reads 6 at cheat time or still 3 (syncs from the slot
  words immediately vs. at spawn/level load). The heal is consistent
  either way; the observed refill amount distinguishes the two.

## Neptune validation (all performed 2026-10-22)

- **Build:** `tools/health-refill-test/` (patcher + manifest + README),
  applied to the hash-guarded retail ISO with the repo's standard patcher
  (input hash and both guard sites verified before writing; output hash
  verified after). Output: `SpongeBob-Movie-USA-HealthRefill-TEST.iso`,
  1,249,804,288 bytes, SHA-256
  `cab04bc299e73f1b261e63e855003a118936468c0e54cd3af36b3fb4e116c304`.
  A one-off pre-build produced the identical hash, which is pinned in the
  manifest.
- **Byte-diff audit** (full 1.25 GB comparison): differences confined to
  the two designed sites — ISO offsets 875417836–875417855 (leaf; 18 of
  20 bytes differ, two bytes are `0x00` in both versions) and
  877266764–877266767 (the `jal` word). Nothing else differs.
- **Round-trip disassembly:** the ELF was sliced out of the built ISO
  (patched ELF SHA-256 `1175a8d7650a7c2a01cb76a955e23f00a73a8847f0d88f277ab6c0547a30b492`)
  and both sites disassemble exactly as designed (`jal 0x10F06C` at
  `0x002D26CC`; the five-word leaf at `0x0010F06C`).
- **Regression:** repo suite re-run after the build — **14/14 patcher
  fixtures passed, 7/7 baseline stages byte-identical**. v0.3,
  HealthMenu, DamageMenu, the Phase 1 CheatSeq ISO, and the retail ISO
  are all preserved. No Free Camera, no level selection.

`tools/health-refill-test/README.txt`: mount the experimental ISO, take
