# v0.4 research track — original cheat entry and Extras (not implemented)

v0.3 is focused exclusively on promoting the already owner-tested HealthMenu. **v0.4** will investigate genuine retail PS2 features, not assume any unused-content unlock exists.

## Verified leads reported in Muse's October 22 handoff

- Retail menu HIP assets still reference cheat-entry UI, including CHEAT_SUCCESS, CHEAT_STEP_GRP, CHEAT_FAILED_GRP and several menu_cheat_*.WAV assets.
- Retail `SB04.INI` mentions seven Function/Cheat extras: **Alt Target Hand, Alternate OOB Hand, Alt Car Horn, Long Antenna, Antenna Fountain, Tiny Foggers, Magnetic Pickup**.
- The retail INI contains G.CheatSpongeball, G.CheatPlayerSwitch, G.CheatAlwaysPortal, G.CheatFlyToggle. Configuration strings alone are **not evidence of reachable runtime implementation**.
- PS2 retail debug stub cluster around 0x403B70–0x403BAC is adjacent to retained controller-debug handler 0x403BB0; upstream DWARF debug symbols use a different layout and cannot be transplanted.

## Implementation gates

1. On Neptune, inventory the actual retail PS2 executable references to cheat input/menu paths and seven Extras; classify each as accessible normally, coded but gated, asset-only, or absent.
2. Map safe trigger controls and read/write state; capture game mode and save-state risks. Prefer toggles that can be reversed without harming progression.
3. Document concrete address evidence and bounded patch-byte windows; run static and instruction-level tests before generating any separate test ISO.
4. Preserve original retail ISO, DamageMenu fallback, and owner-tested HealthMenu, including their verified hashes.
5. Only after owner-approved console validation consider an Extras-related feature release. Do not promote a discovery to a working feature based on strings/assets alone.

Explicit exclusions: **Free Camera and level selection**. Do not publish game images or third-party code.
